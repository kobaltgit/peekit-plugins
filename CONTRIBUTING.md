# Contributing to PeekIt Plugins Ecosystem

Спасибо за интерес к развитию экосистемы плагинов для **[PeekIt](https://github.com/kobaltgit/peekit)**!

Мы приветствуем создание новых плагинов для предпросмотра различных типов файлов, исправление багов и улучшение существующих модулей.

---

## 📋 Требования к плагинам

Каждый плагин, добавляемый в официальный каталог или принимаемый через Pull Request, должен строго соответствовать следующим критериям:

### 1. 100% Автономность (Zero External Requests)
* **Никаких внешних запросов:** Запрещены любые обращения к внешним серверам (`fetch`, `XMLHttpRequest`, `WebSocket`, теги `<script src="https://...">`, шрифты Google Fonts и т.д.).
* Все зависимости, стили, скрипты и шрифты должны быть инлайнены в `index.html` или упакованы локально внутри каталога плагина.
* Плагин обязан полноценно работать без подключения к сети Интернет.

### 2. Безопасность и изоляция
* Плагины исполняются внутри контейнера `<iframe sandbox="allow-scripts">`.
* Не допускается использование опасных конструкций (прямой доступ к `parent.document`, попытки обхода песочницы).
* Обмен данными с приложением PeekIt происходит исключительно через нативный протокол `window.postMessage`.

### 3. Поддержка тем оформления
* Плагин обязан адаптироваться под системную тему Windows:
  ```css
  /* Светлая тема */
  :root, [data-theme="light"] { ... }
  /* Тёмная тема */
  [data-theme="dark"] { ... }
  ```
* Стили интерфейса должны следовать эстетике Windows 11 Fluent Design / Minimalist.

### 4. Производительность и очистка ресурсов
* Мгновенный отклик при открытии (< 50 мс).
* Обязательное освобождение памяти, очистка WebGL-контекстов, отписка от таймеров и событий при закрытии вьюера.

## 🛠 Процесс разработки нового плагина

1. **Создайте копию шаблона:**
   ```bash
   cp -r template plugins/peekit-plugin-<name>
   ```
2. **Заполните `manifest.json`:**
   * Укажите уникальный `id` в обратном доменном формате: `com.peekit.<name>` (или ваш домен: `com.author.<name>`).
   * Перечислите расширения файлов в поле `extensions` (например, `[".ext1", ".ext2"]`).
   * Проверьте манифест на соответствие [plugin-schema.json](plugin-schema.json).
3. **Разработайте функционал в `index.html`:**
   * Ознакомьтесь с [PLUGIN_DEVELOPMENT_GUIDE.md](PLUGIN_DEVELOPMENT_GUIDE.md) для деталей работы протокола сообщений.
4. **Проверьте упаковку:**
   ```bash
   # Упаковать и проверить ваш плагин
   node pack_plugin.cjs plugins/peekit-plugin-<name>

   # Проверить сборку всех плагинов репозитория
   node pack_plugin.cjs --all
   ```
5. **Обновите [registry.json](registry.json):**
   * Добавьте метаданные вашего плагина в массив `plugins`.

## 🚀 Отправка Pull Request

1. Форкните репозиторий и создайте ветку от `main`:
   ```bash
   git checkout -b feature/add-plugin-<name>
   ```
2. Следуйте стандартам Conventional Commits:
   * `feat: add <name> plugin for .ext files`
   * `fix(3d): resolve webgl context loss on close`
   * `docs: update packaging guide`
3. Убедитесь, что `node pack_plugin.cjs --all` отрабатывает без ошибок.
4. Создайте Pull Request с подробным описанием возможностей плагина и тестовыми файлами для проверки.
