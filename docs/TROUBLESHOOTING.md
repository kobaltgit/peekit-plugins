# База частых проблем и решений (Troubleshooting & FAQ)

В этом справочнике собраны типичные ошибки, возникающие при разработке, тестировании и запуске плагинов для **PeekIt**, а также проверенные способы их устранения.

---

## 1. Проблемы при запуске и отображении плагина

### 1.1 «Белый экран» при нажатии Пробела
**Симптом:** Окно PeekIt открывается, но остаётся белым или пустым, контент не загружается.

**Возможные причины и решения:**
1. **Падение скрипта до отправки `PEEKIT_READY` (Ошибка Zero-TDZ):**  
   Если в начале скрипта происходит обращение к неинициализированной переменной (`ReferenceError`), браузер останавливает выполнение, и плагин не успевает отправить сигнал готовности хосту.  
   👉 **Решение:** Проверьте порядок объявления функций и переменных. Запустите `node test_plugins.cjs plugins/your-plugin` — тест эмулирует запуск и укажет точную строку ошибки в V8.
2. **Попытка загрузить внешний ресурс (CDN):**  
   Песочница WebView2 в PeekIt блокирует внешние сетевые запросы. Если в `index.html` есть `<script src="https://cdn...">`, загрузка прервётся.  
   👉 **Решение:** Скачайте библиотеку локально и подключите её из директории плагина либо инлайньте прямо в `index.html`.

---

### 1.2 Плагин бесконечно мигает и перезагружается (Infinite Loop)
**Симптом:** При открытии файла окно предпросмотра быстро мерцает, интерфейс дёргается, нагрузка на процессор возрастает.

**Причина:**  
Плагин отправляет `{ type: 'PEEKIT_READY' }` в ответ на получение данных `{ type: 'PEEKIT_DATA_RESPONSE' }`.  
Хост PeekIt интерпретирует повторный `PEEKIT_READY` как факт перезагрузки страницы плагина и заново начинает цикл инициализации (`PEEKIT_INIT`), запуская вечный круг.

👉 **Решение:**
* Очищайте интервал готовности сразу при получении `PEEKIT_INIT`:
  ```javascript
  if (readyInterval) {
    clearInterval(readyInterval);
    readyInterval = null;
  }
  ```
* **Никогда** не вызывайте отправку `PEEKIT_READY` внутри обработчика `PEEKIT_DATA_RESPONSE`.

---

### 1.3 Текст становится нечитаемым при смене темы (сливается с фоном)
**Симптом:** В светлой теме белый текст на белом фоне или в тёмной теме чёрный текст на чёрном фоне.

**Причина:**  
В стилях CSS использованы жестко захардкоженные цвета (`color: #000`, `background: white`, `color: black`).

👉 **Решение:**  
Используйте исключительно стандартные токены темы:
```css
/* ПЛОХО: */
body { background: #fff; color: #111; }

/* ПРАВИЛЬНО: */
body { background: var(--bg-main); color: var(--text-main); }
```

## 2. Ошибки автоматического тестирования (`npm test`)

### 2.1 `FAIL: I18N check failed (Russian text remaining in EN mode)`
**Симптом:** Тест падает со списком элементов, содержащих русский текст в английском режиме:
```text
FAIL: I18N check failed (Russian text remaining in EN mode): #meta-badge [title: "Размеры · Элементы · Размер"], #val-size [text: "0.0 КБ"]
```

**Причина:**  
Тестовый раннер переключил язык на `en`, но в свойствах `textContent`, `title` (подсказка) или `placeholder` обнаружены символы кириллицы.

👉 **Решение:**
1. Найдите указанные селекторы в выводе ошибки.
2. Добавьте для статических надписей атрибуты `data-i18n` или `data-i18n-title`.
3. Для динамических значений (например, `0.0 КБ` vs `0.0 KB`, `слоёв` vs `layers`) добавьте проверку текущей локали:
   ```javascript
   const unit = currentLocale === 'ru' ? 'КБ' : 'KB';
   valSizeEl.textContent = `${sizeKb} ${unit}`;
   ```

---

### 2.2 `Invalid id: com.author.plugin-name`
**Симптом:** Тест выдаёт ошибку `Invalid id`.

**Причина:**  
Тестовый комплекс требует, чтобы все плагины официального каталога имели идентификатор с префиксом `com.peekit.`.

👉 **Решение:**  
В `manifest.json` укажите идентификатор вида `com.peekit.<slug>` (например, `com.peekit.font-viewer`).

---

### 2.3 `Missing or empty supportedExtensions`
**Симптом:** Тест завершается ошибкой `Missing or empty supportedExtensions`.

**Причина:**  
В `manifest.json` указано поле `extensions`, но отсутствует `supportedExtensions`.

👉 **Решение:**  
Укажите оба массива в `manifest.json` для 100% совместимости:
```json
"supportedExtensions": [".svg", ".svgz"],
"extensions": [".svg", ".svgz"]
```

## 3. Ошибки упаковщика пакетов (`pack_plugin.cjs` / `npm run pack`)

### 3.1 `Security audit failed: External script CDN loading detected`
**Симптом:** Упаковщик отказывается собирать файл `.pkit` с ошибкой проверки безопасности.

**Причина:**  
В одном из HTML или JS файлов обнаружен паттерн загрузки внешних скриптов/стилей или сетевых вызовов (`fetch('https://...')`, `<script src="http...>`).

👉 **Решение:**
* Скачайте скрипты вендора в локальную папку плагина.
* Если сетевой вызов использовался для получения документации или ссылки на сайт, вынесите его в атрибут `href` ссылки или манифест, но не вызывайте программно через `fetch`.

## 4. Производительность и большие файлы

### 4.1 Плагин зависает на файлах больше 20–50 МБ
**Симптом:** При открытии тяжелого файла окно предпросмотра «замирает» на несколько секунд, интерфейс не реагирует на клавиши.

**Рекомендации:**
1. **Немедленный статус загрузки:**  
   Покажите индикатор прогресса сразу при получении `PEEKIT_INIT`, чтобы пользователь видел, что файл читается.
2. **Асинхронный парсинг чанками:**  
   Для больших текстовых или JSON-файлов разбивайте обработку на части через `requestAnimationFrame` или `setTimeout`, не блокируя основной поток UI.
3. **Очистка ресурсов:**  
   При закрытии окна или переключении на другой файл обязательно освобождайте WebGL-контексты (`gl.getExtension('WEBGL_lose_context')?.loseContext()`), отменяйте активные таймеры и очищайте ссылки на большие буферы памяти.
