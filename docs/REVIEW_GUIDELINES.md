# Регламент проверки плагинов (Review Guidelines)

Любой Pull Request, добавляющий новый плагин или обновляющий существующий модуль в каталоге `plugins/` и `registry.json`, проходит обязательную автоматическую и ручную проверку мейнтейнерами экосистемы **PeekIt**.

---

## 0. Обязательный автоматический шлюз качества (`npm test`)

Перед созданием Pull Request автор **обязан** убедиться, что автоматический проверочный комплекс завершается со статусом `0` без единой ошибки:

```bash
npm test
# или проверка конкретного плагина:
node test_plugins.cjs plugins/peekit-plugin-<slug>
```

PR не будет принят, если плагин не проходит хотя бы один из 6 этапов валидации:
1. **Manifest Schema:** наличие всех обязательных полей, валидный SemVer, префикс `com.peekit.`, существование файла `entry`.
2. **Strict Offline:** сканирование кода на отсутствие внешних URL и CDN.
3. **V8 Syntax:** компиляция встроенных скриптов движком V8 без синтаксических ошибок.
4. **Runtime Lifecycle & Handshake:** эмуляция отправки `PEEKIT_READY` и ответа на `PEEKIT_INIT`.
5. **Theme Engine:** отсутствие исключений при смене темы на лету (`light` ⇄ `dark`).
6. **I18N Completeness:** наличие кнопки `#btnToggleLang`, корректная смена языка и отсутствие непереведённого русского текста в режиме `en`.

---

## 1. Безопасность и песочница (Критично)

* **100% Offline (Zero External Requests):**
  * Запрещены любые вызовы `fetch()`, `XMLHttpRequest`, `WebSocket`, `WebRTC`.
  * Запрещено подключение внешних ресурсов: `<script src="https://...">`, `<link href="https://fonts.googleapis.com...">`, `<iframe src="...">`. Все шрифты, иконки и библиотеки обязаны быть упакованы локально в плагин.
* **Запрет небезопасного динамического кода:**
  * Запрещены вызовы `eval()`, `new Function(...)` и `setTimeout('строка кода')`.
* **Изоляция песочницы:**
  * Плагин выполняется внутри `<iframe sandbox="allow-scripts">`. Попытки обращения к `window.parent.document` или обхода песочницы расцениваются как критическая уязвимость.
* **Безопасный IPC:**
  * Всё взаимодействие с хостом осуществляется исключительно через `window.postMessage` с валидацией структуры сообщений.

## 2. Качество сборки и размер пакета

* **Каноническая упаковка:**
  * Пакет `.pkit` обязан генерироваться утилитой `pack_plugin.cjs` (нормализация окончаний строк, нулевые таймстемпы архива для детерминированного хеша).
* **Контрольная сумма SHA-256:**
  * Хеш архива в `registry.json` должен строго совпадать с реальным SHA-256 файла в `dist/`.
* **Размер бандла:**
  * Рекомендуемый размер: **до 5–10 МБ**.
  * Предельный размер для плагинов с тяжёлыми WASM/WebGL библиотеками (Three.js, SQLite, FFmpeg): **до 25 МБ**.
* **Чистота репозитория (No Junk):**
  * В бандл и директорию плагина не должны попадать тестовые файлы пользователей, логи, исходники TypeScript (`.ts`), карты кода (`.map`), папки `.git`, `.vscode`, `node_modules`.

## 3. Требования к манифесту (`manifest.json`)

* Манифест обязан соответствовать [`plugin-schema.json`](file:///d:/Projects/active/peekit-plugins/plugin-schema.json).
* **Идентификатор `id`:** обязан начинаться с префикса `com.peekit.<slug>` (например, `com.peekit.svg-studio`).
* **Обязательные поля:** `id`, `name`, `version` (SemVer 2.0), `author`, `description`, `category`, `entry`, `min_peekit_version`.
* **Расширения:**
  * Массив `supportedExtensions` (обязателен для тестов) и массив `extensions` (для JSON Schema) должны содержать расширения в нижнем регистре с точкой: `[".svg", ".svgz"]`.
* **Иконка:** векторная SVG-иконка `icon.svg` размером 24×24 или 32×32 px в корне плагина.

---

## 4. Интерфейс, темы и интернационализация (UI/UX)

* **Поддержка тем:** плагин обязан корректно отображаться в светлой и тёмной теме Windows с использованием стандартных CSS-переменных (`--bg-main`, `--bg-surface`, `--text-main`, `--accent`).
* **Двуязычная локализация (RU/EN):**
  * Наличие кнопки `#btnToggleLang` в шапке/тулбаре.
  * Реакция на событие хоста `PEEKIT_LANGUAGE_CHANGED` без перезагрузки страницы.
  * Глубокий перевод всех видимых элементов: заголовков, кнопок, тултипов (`title`), плейсхолдеров и динамических бейджей.
* **Отказоустойчивость:**
  * Соблюдение порядка инициализации **Zero-TDZ** (отсутствие ошибок `ReferenceError` до отправки `PEEKIT_READY`).
  * При повреждении или невозможности чтения файла плагин обязан перехватить ошибку (`try/catch`), отобразить понятное сообщение пользователю и отправить хосту `PEEKIT_ERROR`. Плагин не должен зависать на белом экране.
  * **Запрет цикла:** плагин не должен отправлять `PEEKIT_READY` в ответ на `PEEKIT_DATA_RESPONSE`.
