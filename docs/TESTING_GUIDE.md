# Руководство по тестированию и верификации плагинов (Testing Guide)

Надёжность и мгновенный отклик — ключевые требования к плагинам **PeekIt**. Ошибка рендеринга или падение скрипта в песочнице приводят к «белому экрану» или зависанию предварительного просмотра у пользователя.

Для предотвращения дефектов в репозитории действует трехуровневая система верификации:
1. **Автоматический тестовый раннер (`npm test`)** — проверяет синтаксис, манифесты, песочницу, рукопожатие, темы и локализацию.
2. **Браузерная песочница (`template/mock-host.html`)** — интерактивная отладка рендера и обмена сообщениями в Chrome/Edge.
3. **Интеграционное тестирование в десктопном PeekIt** — проверка реального поведения в Windows Explorer по клавише Пробел.

---

## 1. Автоматизированный тестовый комплекс (`npm test`)

Перед отправкой Pull Request и перед сборкой `.pkit` пакетов обязательно запускается скрипт `test_plugins.cjs`:

```bash
# Проверить ВСЕ плагины в репозитории:
npm test

# Проверить только один конкретный плагин:
node test_plugins.cjs plugins/peekit-plugin-myformat
```

### 🔍 Что проверяют 6 фаз тестирования:

| # | Фаза теста | Что проверяется | Типичная причина сбоя |
| :---: | :--- | :--- | :--- |
| **1** | **Manifest Schema** | Наличие `manifest.json`, префикс `id: "com.peekit.*"`, валидный SemVer, существование файла `entry`, наличие непустого массива `supportedExtensions`. | `id` не начинается с `com.peekit.` или расширения указаны без точки. |
| **2** | **Strict Offline** | Сканирование всех файлов на отсутствие внешних URL (`https://`), CDN-скриптов, внешних шрифтов Google Fonts, `fetch`, `XMLHttpRequest`, `WebSocket`. | Подключение библиотеки с CDN (`cdnjs`, `unpkg`, `jsdelivr`) вместо локального бандла. |
| **3** | **V8 Syntax** | Извлечение всех `<script>` блоков из `index.html` и их компиляция через движок V8 (`vm.Script`) без исполнения. | Опечатки в коде, незакрытые скобки, неэкранированные спецсимволы в строковых литералах. |
| **4** | **Lifecycle & Handshake** | Запуск плагина в виртуальном DOM-окружении (WebView2 mock). Проверяется отправка `PEEKIT_READY` и регистрация обработчика `message`. | Скрипт упал из-за нарушения порядка Zero-TDZ до вызова `postMessage`. |
| **5** | **Theme Engine** | Отправка событий `PEEKIT_THEME_CHANGED` для светлой и тёмной тем. Проверяется отсутствие исключений при смене темы на лету. | Обращение к несуществующим элементам или жёстко захардкоженные inline-цвета. |
| **6** | **I18N Completeness** | Наличие кнопки `#btnToggleLang`, реакция на клик по ней, отправка `PEEKIT_LANGUAGE_CHANGED` с `language: 'en'`. Проверяется отсутствие оставшегося русского текста во всех элементах. | Забытый русский текст в `title`, `placeholder` или динамических счетчиках в режиме EN. |

## 2. Локальная отладка в браузере (`mock-host.html`)

Для быстрой разработки и отладки визуальной части используйте интерактивный стенд [`template/mock-host.html`](file:///d:/Projects/active/peekit-plugins/template/mock-host.html).

### Как запустить:
1. Откройте файл [`template/mock-host.html`](../template/mock-host.html) в Google Chrome или Microsoft Edge (просто дважды кликните по файлу или перетащите его в окно браузера).
2. **Шаг 1. Выберите плагин (интерфейс вьюера):**
   * В выпадающем списке **Плагин** выберите готовый плагин (например, *SVG Studio*, *3D Viewer*, *Word Document* и др.).
   * Если вы разрабатываете свой плагин, выберите пункт *«Свой путь к index.html...»* и укажите относительный путь от `mock-host.html` к `index.html` вашего плагина:
     ```text
     ../plugins/peekit-plugin-myformat/index.html
     ```
   * Нажмите кнопку **🔄 Перезагрузить**. Плагин загрузится во фрейм и начнёт цикл рукопожатия `PEEKIT_READY`.
3. **Шаг 2. Выберите тестовый файл контента (данные для просмотра):**
   * Нажмите кнопку **Выберите файл** (или *Обзор*) в блоке «Тестовый файл».
   * Укажите любой реальный файл поддерживаемого формата на вашем диске (например, `diagram.svg`, `document.docx` или `model.stl`).
   * Эмулятор хоста считает этот файл с диска и передаст его в плагин в виде бинарного буфера `ArrayBuffer` через сообщение `PEEKIT_DATA_RESPONSE`.
4. **Шаг 3. Проверьте реакцию интерфейса:**
   * Нажимайте кнопки **🌙 Тема: Dark / Light** и **🌐 Язык: RU / EN** для проверки адаптивности без перезагрузки.
   * В панели справа (**PeekIt IPC Activity Log**) отслеживайте живой обмен событиями:
     * Золотым цветом помечаются сообщения хоста: `HOST ➔ PLUGIN (PEEKIT_INIT, PEEKIT_DATA_RESPONSE)`.
     * Бирюзовым цветом помечаются ответы плагина: `PLUGIN ➔ HOST (PEEKIT_READY, PEEKIT_REQUEST_DATA)`.

## 3. Интеграционное тестирование в десктопном PeekIt (Windows)

Для окончательной проверки работы в реальной операционной системе:

### Шаг 1. Копирование плагина в директорию PeekIt
Скопируйте папку с плагином в рабочую директорию плагинов установленного приложения:

```powershell
# Для установленной версии PeekIt:
Copy-Item -Recurse -Force plugins/peekit-plugin-myformat "$env:APPDATA\PeekIt\plugins\"

# Для портативной версии (например, D:\Peekit):
Copy-Item -Recurse -Force plugins/peekit-plugin-myformat "D:\Peekit\plugins\"
```

### Шаг 2. Проверка горячих клавиш в Проводнике
1. Откройте папку с тестовыми файлами в Проводнике Windows (`explorer.exe`).
2. Выберите файл поддерживаемого формата и нажмите **Пробел**.
3. Убедитесь, что:
   * Окно предпросмотра появляется мгновенно без видимого белого мерцания.
   * Текст заголовка и бейджи соответствуют открытому файлу.
   * Повторное нажатие **Пробела** или **Esc** моментально закрывает окно.
   * Нажатие стрелок на клавиатуре переключает предварительный просмотр на соседние файлы.

## 4. Отладка через Microsoft Edge DevTools

Плагины исполняются внутри контейнера Microsoft Edge WebView2. Если плагин ведёт себя неожиданно:

1. Запустите хост-приложение PeekIt с флагом удалённой отладки:
   ```cmd
   PeekIt.exe --remote-debugging-port=9222
   ```
2. Откройте в браузере Edge страницу:
   ```text
   edge://inspect
   ```
3. В списке доступных WebView вы увидите активный фрейм плагина. Нажмите **Inspect**, чтобы получить полноценную консоль DevTools (Elements, Console, Network, Memory).
